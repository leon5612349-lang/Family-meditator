# Семейный медиатор

Telegram-бот + Mini App для пар: безопасный живой диалог по методу ЭФТ
(эмоционально-фокусированная терапия, Сью Джонсон) с «Водопадом» —
структурой каскадов, Озёр и психологических разборов.

Бот **не переформулирует** сообщения: партнёры пишут друг другу напрямую,
а нейросеть работает тремя точечными инструментами:

| Инструмент | Кто вызывает | Что делает |
|---|---|---|
| **Водопад** (therapy.py) | оба | Ведёт пару по каскадам: ступени-вопросы (A/B) → «Озеро» (свободное общение) → следующий каскад. Озеро проходится, только когда оба нажали «🌊 Дальше» |
| **Расшифровка** (analyze) | получатель сообщения | Глубокий разбор резкого сообщения по плану ЭФТ: факты → эмоции и маски → истинная потребность → как сказать Я-сообщением |
| **Проверка безопасности** (check_safety) | оба | Резкое диагнозное остаётся в диалоге, но реальные угрозы блокируются и не доходят до партнёра |

## Структура проекта

```
Family-meditator/
├── backend/
│   ├── main.py        # Telegram-бот (aiogram) + одновременный запуск FastAPI
│   ├── api.py         # FastAPI: /api/send, /api/history, /api/analyze,
│   │                  # /api/next-cascade, /api/expand, /api/finish
│   ├── therapy.py     # «Водопад»: каскады, Озёра, тексты ступеней (ЭФТ)
│   ├── llm.py         # Единый слой DeepSeek: check_safety, расшифровка,
│   │                  # резюме сессии, совет
│   └── database.py    # SQLite (aiosqlite): users, messages, sessions,
│                      # session_partners, finish_locks
├── frontend/
│   └── index.html     # Telegram Mini App: живой чат, карточка ступени,
│                      # кнопки «Дальше» и «Расшифровать»
├── .env.example       # Шаблон секретных ключей
└── README.md
```

## Как проходит сессия

1. **Онбординг в боте**: имя (текстом) + пол (кнопками) + суть конфликта.
2. Партнёр подключается по ссылке-приглашению и проходит то же знакомство.
3. Стартует **Каскад 1, ступень A** — бот задаёт вопрос партнёру 1.
4. Партнёры отвечают «как есть» (живой диалог, без посредника).
5. Ответ на ступень двигает пару дальше; ответив на оба вопроса, они
   попадают в **Озеро** — свободное общение под присмотром.
6. Из Озера идёт только общий клик «🌊 Мы услышали друг друга. Дальше»
   (в боте и в Mini App — один и тот же флаг в базе).
7. Каскады 2 (уязвимость) и 3 (интеграция) ведут пару к **Шаг 5 — Наши решения**.
8. `/finish` (или кнопка в Mini App) — DeepSeek резюмирует всю сессию
   для **обоих** партнёров.
9. В любой момент входящее сообщение можно **расшифровать**: в боте —
   кнопка под перенесённым сообщением, в Mini App — чип «💡 Расшифровать»
   под серым пузырём.

## Быстрый старт

### 1. Виртуальное окружение и зависимости

```bash
python -m venv venv
.\venv\Scripts\Activate.ps1        # Windows (PowerShell)
pip install -r backend/requirements.txt
```

### 2. Ключи

```bash
cp .env.example .env
```

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | Токен бота от [@BotFather](https://t.me/BotFather) |
| `ZVENO_API_KEY` | Ключ [ZvenoAI](https://zveno.ai) — все текстовые и аудио-запросы идут через него |

`.env` не публикуется в репозитории.

### 3. Запуск

```bash
python backend/main.py
```

Поднимает одновременно Telegram-бота (long polling) и FastAPI-сервер
Mini App на `http://127.0.0.1:8000`. Только API (без бота, для фронтенда):

```powershell
uvicorn api:app --host 127.0.0.1 --port 8000   # из папки backend/
```

### 4. Тесты из браузера (без Telegram)

`/api/send`, `/api/history` и остальные эндпоинты принимают `user_id`
напрямую при **пустом** `init_data` (fallback для отладки через Ngrok).
`TEST_USER_ID` задаётся в `frontend/index.html`, свой ID — команда `/myid`
у бота. ⚠️ На публичном хосте fallback означает «знать Telegram ID = войти
под ним»: перед реальным продакшеном ограничьте его локалхостом или
отключите.
